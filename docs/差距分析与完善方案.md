# A01 赛题差距分析与完善方案

> 对照《2026"数字马力杯"A01 AI能力测评智能体》赛题要求与当前项目 v1.5.0 实测状态。
> 分析日期：2026-08-17。依据：赛题原文、代码实测（50/50 测试通过、76 项 API 冒烟通过）、项目文档与提交材料核对。

## 一、已满足部分（对照赛题逐项）

### 1. 能力维度定义与题库（评分要点 25%，基本达标）

| 赛题要求 | 当前状态 |
|---|---|
| 至少 5 个 AI 能力维度 | ✅ 六维：基础认知 16 题、提示词工程 16 题、工具使用 16 题、结果评估 17 题、人机协同 16 题、伦理合规 15 题 |
| 每维 ≥10 基础 + 5 进阶 | ✅ 每维 50 题（客观 30 + 主观 20），难度 1/2/3 分层，大幅超标 |
| 分级清晰 | ✅ L1~L5 等级 + 可观察行为标准（`question_bank/ability_standards.json`），页面可查阅 |
| 题目质量 | ✅ 结构校验通过、答案位置四选项均衡（A/B/C/D 各 25%）、重复题 0 组；⚠️ 3 题题干过短待盲审 |

### 2. 三种测评模式（任务要求，全部实现）

- ✅ **客观题测评**：198 道（单选 180 + 判断 18），作答时选项随机打乱、提交后保序回看
- ✅ **对话式测评**：AI 助手对话窗口（真实 ant-line 已调通，Ling-3.0-flash），对话记录计入评分证据
- ✅ **实操任务测评**：3 道实操任务 + 过程引导（结构化引导 6 轮）+ 证据文件上传
- ➕ 额外实现代码任务（2 题）与图像鉴别任务（2 题），满足多模态建议项

### 3. 自适应测评机制（评分要点 25%，机制已实现）

- ✅ 前 12 题六维分层覆盖 → 按置信度/薄弱维度补测 → 末段固定开放/实操/对话任务
- ✅ 同一场题目不重复、15/18/25 三档、提前停止、阶段题号导航
- ⚠️ 仅仿真验证（100 份合成样本分类一致率约 0.81），**无真实学员定位准确率**

### 4. 自动评分（评分要点 20%，机制完整、数据缺失）

- ✅ 三层评分：百宝箱智能体 → ant-line → 规则降级（`rubric-fallback-v1` 显式标注）
- ✅ JSON 结构校验、分数边界限制、低置信度强制人工复核
- ✅ 人工双评 + 第三人裁决 + 一致性指标（Pearson / 二次加权 Kappa）
- ⚠️ **致命短板**：0.922 的模型—人工一致性是"模拟教师 A/B"之间的相关，**非真实教师评分**；阈值由仿真样本校准（`config/level_thresholds.json` 自述"不代表真人常模"）

### 5. 报告与可视化（评分要点 20%，功能完备）

- ✅ 六维雷达图、综合分、等级、置信度、逐题证据、错题解析、薄弱项建议、训练资源推荐

## 三、完善方案（按优先级分三个阶段）

### 阶段 1：真实验证与演示（第 1~2 周，最高优先）

**目标：把"仿真验证"升级为"真实数据验证"，产出演示视频。**

1. **执行真实试测（10 → 30 人）**
   - 按 `docs/10人预测试执行包.md` 组织：局域网 + cloudflared 隧道双通道
   - 覆盖初学/中等/熟练三段样本，25 题模式，记录完成率、用时、题目曝光
   - 收集歧义题、操作问题、报告理解度反馈
2. **真实教师双评**
   - 用系统"人工复核"模块：2 名教师独立评开放题（分差 ≥20% 第三人裁决）
   - 导出 CSV，计算真实模型—人工 Pearson、二次加权 Kappa、双评相关
   - 产出 `docs/真实试测验证报告.md`（替代/并列 04 仿真报告，明确标注数据来源）
3. **用真实数据重新校准阈值**
   - 运行 `tools/calibrate_level_thresholds.py`（已存在）以真实样本校准 L1~L5 切点
   - 更新 `config/level_thresholds.json` 并标注 `evidence_scope: real_cohort`
4. **题目质量分析一轮**
   - 按曝光 ≥10、正确率（>0.9 过易 / <0.2 过难）、区分度 <0.15 规则筛题
   - 修订或停用问题题（系统已支持启停 + 版本记录）
5. **录制演示视频（≤10 分钟，≤150MB）**
   - 脚本：开始测评 → 客观题作答（选项乱序）→ 主观题 AI 助手真实对话 → 证据上传 → 报告（雷达图/建议/训练资源）→ 教师看板 → 企业岗位闭环
   - 画面要求：不出现学校/指导教师信息（赛题规定）

### 阶段 2：质量与体验加固（第 3~4 周）

6. **题库盲审**：1 名非出题成员盲审 300 题，重点处理 3 个题干过短题；盲审记录归档
7. **对话过程评分增强**：将 AI 助手对话轮数、追问信息量、过程结构化程度纳入人机协同评分（`llm/scorer.py` 的 context 通道扩展），并保持"不冒充模型评分"的降级标注
8. **移动端真机验证**：iOS/Android 各 1 台跑通全流程，修复触控/布局问题
9. **并发验证**：用 locust/自写脚本压测 50 并发开始测评+提交；SQLite 开启 WAL、加连接超时；输出压测结论或 PostgreSQL 迁移方案
10. **学员数据自助管理**：新增"我的数据"页（导出本人测评记录 JSON / 删除账号及数据），补齐个保法合规点

### 阶段 3：加分项与收尾（第 5~6 周）

11. **开源代码清单**：README 附录列出使用的开源组件（FastAPI、uvicorn、pydantic、SQLite、cloudflared 等）及用途
12. **伦理深化**：AI 助手代答检测（提交答案与对话高度雷同时提示）、防过度依赖提示语、偏见规避说明文档
13. **生态整合落地设计**：输出与"AI 智能·教学辅具"数据打通的最小 API 设计（能力画像标准 JSON Schema）、证书/学分/招聘衔接流程图
14. **图像题库扩充**：替换为真实 AI 生成图 vs 真实照片对比集，扩充至 5~10 组
15. **大赛通用材料**：S1 方案概要（800 字）、S2 解决方案（含三角色分工）、S3 展示 PPT、团队过程材料、原创承诺书
16. **代码沙箱探索**（可选加分）：受限执行环境跑代码任务判题，或文档说明接入 API 判题方案

## 四、结论

- **已满足**：功能完整度在参赛原型中处于前列 —— 六维模型、三种测评模式、六项企业级技术点全部实现，平台工程（三角色/安全/题库后台/企业闭环）超出赛题基础要求，四份提交材料文档齐备，系统 50/50 测试通过可稳定运行。
- **最大风险**：评分要点合计 45% 权重（自适应 25% + 评分准确性 20%）目前只有仿真证据，**必须用真实试测数据补上**；演示效果 20% 缺少视频与稳定地址。
- **建议投入顺序**：真实试测与双评（P0）> 演示视频（P0）> 盲审与题目修订（P1）> 合规与生态设计（P2）。现有代码与工具链（复核模块、校准脚本、导出 CSV、隧道脚本）已为上述工作做好准备，人力投入集中在"组织试测 + 数据分析 + 录制视频"三件事上。
