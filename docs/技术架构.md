# 技术架构与关键选型

## 架构组成

- 前端：原生HTML、CSS与JavaScript，单页响应式界面，无外部字体和图片依赖。
- API：FastAPI，提供测评、报告、题库、复核、统计和导出接口。
- 数据库：SQLite，适合本地演示和小规模试测；正式部署建议迁移PostgreSQL。
- 测评引擎：按维度、题型和难度分层随机，结合得分证据与置信度自适应补题。
- 评分适配层：客观题确定性评分；开放题本地量表初评；预留外部模型适配接口。
- 可视化：浏览器Canvas雷达图和CSS统计图表。

## 数据实体

- users：学员与班级/团队。
- tests：测评状态、自适应引擎状态和完成时间。
- answers：原始作答、题目快照标识、得分、用时和初评反馈。
- question_items：题目当前版本、启停状态和来源。
- question_versions：每次修改、导入或启停操作的版本记录。
- human_reviews：评审人独立评分与评语。
- review_resolutions：双评分歧的最终裁决。

## 数据一致性

每次测评使用独立UUID。题目不执行物理删除，只允许停用，因此历史答案仍可追溯。管理员修改题目后生成新版本；新测评读取当前启用题目，历史测评继续保留已答题目ID与反馈。

## 安全边界

- 教学管理、题库答案、复核和导出接口要求 `X-Admin-Key`。
- 默认密钥仅用于本地演示；部署必须通过 `A01_ADMIN_KEY` 修改。
- 外部模型密钥只能通过环境变量配置，不写入源码和数据库。
- 正式部署需增加HTTPS、账号登录、角色权限、审计日志、CSRF策略、限流和数据库备份。

## 百宝箱适配位置

百宝箱只需接入 `llm/scorer.py` 的评分适配层。题库、测评引擎、人工复核、统计、报告和导出不依赖百宝箱。接入后仍必须保留JSON校验、失败降级、调用审计和人工复核。
